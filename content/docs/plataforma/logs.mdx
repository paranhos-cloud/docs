Cada requisição atendida por um projeto vira uma linha de log. É o que mostra se uma página está
respondendo, quanto tempo leva e quais caminhos dão erro.

## O formato da linha

```txt
GET /sobre 200 12ms requestId=8f3c1b2a4d5e6f70
```

Método, caminho, código HTTP, tempo de resposta e o `requestId` — o identificador daquela
requisição na rede da Paranhos. É por ele que o suporte encontra o que aconteceu com um acesso
específico, então vale guardá-lo ao relatar um problema.

O caminho é registrado sem a query string: o que vem depois do `?` não entra no log, porque URLs
costumam carregar token de sessão, e-mail e outros dados de quem acessa.

## Níveis

O nível vem do código da resposta:

| Nível | Códigos |
| --- | --- |
| `info` | 2xx e 3xx |
| `warn` | 4xx |
| `error` | 5xx |

Na página **Logs** você filtra por nível e busca por trecho do caminho. São exibidas as 500 linhas
mais recentes.

## Retenção

Os registros ficam guardados por **7 dias**; depois disso são apagados. Ainda não existe exportação
para guardar períodos maiores.

<Callout type="info">
  Aqui estão os acessos ao site. O log do **build** fica na execução do GitHub Actions, com link na
  página do deploy — veja [Deploys](/plataforma/deploys).
</Callout>
